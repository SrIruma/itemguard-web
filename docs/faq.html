FAQ

The questions that come up most often, answered short.

What does it need to run?

Paper 1.21 or newer and Java 21. No other plugin is required: the SQLite, MySQL and PostgreSQL drivers ship inside the jar, and LuckPerms is used when installed but never needed.

Does it support Spigot, Forge or Fabric?

ItemGuard is a Paper plugin. It needs the Paper API at 1.21 or newer; a fork with the same plugin API works, and Paper itself is the supported target.

Do I need a database server?

No. SQLite is the default: a single itemguard.db file, nothing leaves the machine. MySQL and PostgreSQL are supported when you outgrow a file. Either way, one server per database — enforced, not advised. See Database.

Can I run the same plugin on two servers with one database?

No, and the plugin refuses instead of silently misbehaving. Its tables are full of world names and coordinates, which only mean something to the world they came from. Give each server its own schema.

Where is the item’s id kept?

In the item’s NBT, written at delivery time. The record in the database says where it is; the two are kept in step, and the plugin never drops items on the ground or duplicates them.

Why can’t my players pick up or drop their bought item?

Because droppable and pickupable default to off — a conservative default, so protection is on from the first delivery. A dropped un-pickupable item is sealed where it falls and the owner takes it back with /ig reclaim. Give away what you mean: see Flags.

What happens when a container with my item explodes?

If explosion-protected is on (the default), the block survives and the item with it. When an item is genuinely lost, a recoverable copy can be rebuilt with /ig regenerate, or pulled back from wherever it is with /ig recover.

Someone bought something and it is gone. How do I make it right?

Ask for the facts: /ig info <id> opens the item's record, and the history button on it opens the full event list, including the last place it was seen. Then decide between /ig recover (take it back in one piece) and /ig regenerate (rebuild it from the stored copy).

Who counts as the owner, and how does a sale get handed over?

The owner is the one protection answers to: the only one who may break the placed block, the one explosions rescue the item for, and the one sealed items return to. /ig owner hands the item and its ownership over, confirmed by the current owner — nobody can quietly move an item out from under a hijacked account. See Ownership & transfer.

How do I let my store plugin fulfil purchases without full admin?

The console is blocked except for the subcommands in console.allow, which defaults to give — a store plugin such as Tebex can run /ig give <player> <template> and nothing else. Read-only commands (version, reload, help, integrations, permissions, allow) bypass the list.

Why does nothing work—I’m an operator and I still get refused?

Every permission defaults to false, for operators included. Grant itemguard.admin, or on a test server where everyone joins as operator set console.ops-are-admins: true. /ig permissions shows exactly what you hold. See Permissions.

Can I change the wording, or translate it myself?

Yes. Every message comes from plugins/ItemGuard/translations/, one editable file per language with documented colour and placeholder support, and /ig reload picks changes up without a restart. See Translations.

Is it free, and where do I get it?

ItemGuard is a paid plugin, sold on BuiltByBit. If you would rather see it run before you spend anything, BuiltByBit has a trial server with the plugin already installed — you join it from the plugin’s listing.

Can I try it before I buy?

Yes. The quick start above is the whole installation; the trial server is for playing with the plugin in game. You join it from the listing on BuiltByBit.

Did something break. What do I read first?

The start-up block, which prints facts — state, engine in use with credentials masked, and a named problem with a suggested fix when it cannot start. The whole thing also goes to plugins/ItemGuard/logs/ when file logging is on. Then the FAQ page you are on. Then the issue tracker, or the email address at the bottom of the page if you would rather not use an account.

How do I report a problem?

Either way at the bottom of this page:

  • An issue on the documentation repository. It is public, anyone can open one, and it needs no account beyond GitHub. Search the open issues first — a lot of reports are the same config mistake, and finding it already answered is faster than waiting.
  • An email to MrTsumugi@proton.me, which reaches both of us. Slower, and it has no public record, so it suits anything you would rather not post in the open.

Either way, the start-up block and plugins/ItemGuard/logs/ are the first thing worth attaching: most problems are answered by the line that names the engine in use and the problem it found.

Abuse and security reports do not go in public. If the report is about someone abusing the plugin rather than it misbehaving, use the email. A public issue is a permanent, searchable record.
