Flags

A flag is a behaviour switch with a conservative default. Seven of them decide what a protected item is allowed to do — nothing more, nothing less.

Precedence: the item wins, then the template, then the default

The seven flags

FlagDefaultMeaning
droppablefalseThe holder may drop the item on the ground
pickupablefalseAnyone, including the owner, may pick it up
movabletrueIt may be moved between inventories by click or drag
hopper-transfertrueA hopper may pull the item out of a container
breakable-by-othersfalseSomeone other than the owner may break the placed block
explosion-protectedtrueA container explosion rescues it rather than destroying it
recoverabletrueA lost copy may be rebuilt by /ig regenerate
“Off” is the conservative direction for a loss; “on” for a movement Drop, pickup and breaking by others are the losses ItemGuard exists to prevent, so their flags default to off. Moving between your own slots and an explosion's blast were never stopped by the plugin and cost nothing, so movable, hopper-transfer, explosion-protected and recoverable default to on — each keeps exactly the freedom ItemGuard had before flags existed.

Where a flag lives

A flag can be set at three levels, and the more specific one wins:

  1. Item — pinned on a single tracked item.
  2. Template — inherited by every item created from it.
  3. Default — the conservative value above.

An item that stops pinning a flag falls back to the template, and a template that stops pinning one falls back to the default. Nothing gets stuck.

Reading and writing flags

/ig flag Sword                        # the seven flags, on a screen
/ig flag Sword droppable=true         # pin the flag on the template
/ig flag TI-0123 pickupable=true recoverable=false
/ig flag TI-0123 droppable=template   # fall back to the template again

Without a value, the command is a report, and for a player it is a screen: every flag with its value, the layer that value came from, the default, and one sentence on what it does — the fastest way to answer “why does this item behave like this”. The console prints the same facts as text. See In-game screens.

It is read-only on purpose. A menu of toggles would let one stray click decide how an item behaves, and an item that cannot be picked up is the sort of bug nobody could trace back, so changing a flag stays a sentence with a value in it.

Flags on a single delivery

/ig give accepts the same flags k=v option to pin values on one delivery only, without touching the template:

/ig give Steve Sword amount 64 flags droppable=true recoverable=false quiet

Handy for event items you want to fall to the ground but never be stolen, or giveaway items that become returnable on death.

Worked variations

ScenarioFlags
A spawner nobody may ever takedroppable=false pickupable=false movable=false hopper-transfer=false breakable-by-others=false explosion-protected=true recoverable=true
A cosmetic item for events, allowed to be droppeddroppable=true pickupable=false breakable-by-others=false
A key that must be passable between staffdroppable=false pickupable=true movable=true hopper-transfer=false
A quest item that may be genuinely lostrecoverable=false
pickupable=false and the ground An un-pickupable item that gets dropped lies in the open forever: nobody can pick it up, not even the owner. That is what seals are for — the dropped item gets a bedrock seat and a label, and the owner takes it back with /ig reclaim.
