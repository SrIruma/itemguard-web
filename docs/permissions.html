Permissions

Every permission defaults to false, so not even operators hold them until they are granted — with one deliberate exception.

18 nodes · itemguard.admin bundles them all

The one exception itemguard.reclaim defaults to true so that owning an item is enough to get it back. Revoke it on a group and its players are sent to an admin instead.

Two shorthands

itemguard.admin arrives two ways, and ItemGuard resolves both itself, so they work even without a permission plugin:

  • itemguard.admin — every node at once, also declared in plugin.yml as a children: list for LuckPerms, Vault and friends.
  • itemguard.* — the wildcard prefix, for whatever wildcard support the permission plugin has.

With LuckPerms

/lp group default permission set itemguard.admin true

Granting the seventeen nodes one by one is never necessary. LuckPerms is not a dependency and is not shaded: ItemGuard only ever calls sender.hasPermission(...), which every permission plugin implements.

When everybody who joins is an operator

On a test server, a preview, or anything behind a launcher that gives every player operator, the policy above is a problem: everybody is an operator and no operator holds any of the seventeen nodes, so the owner can install the plugin and still not run a single command.

console:
  ops-are-admins: true

Operator status becomes the whole policy. It defaults to false and it does not touch the permissions: a non-operator is refused exactly as before. Two choices worth knowing:

  • Read once, at start-up. /ig reload does not change it, so /ig permissions can never contradict itself.
  • A refusal tells an operator about it. Denied operators are shown the switch; everyone else just sees the missing node, because for them the node is the answer.

Finding out what you actually hold

/ig permissions

Prints every node with a yes or a no, plus the name of the message file in use. It needs no permission of its own, because the people who need it are exactly the ones who cannot run anything else. When a subcommand is refused, the message names both the node and the subcommand:

You do not have itemguard.add, which /ig create needs.
