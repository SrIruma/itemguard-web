Quick start

From a jar in plugins/ to a guarded item in under a minute.

Estimated time: 3 minutes · Paper 1.21+ · Java 21

1. Requirements

  • Paper 1.21 or newer (or a fork with the same API).
  • Java 21.
  • No other plugin. The SQLite, MySQL and PostgreSQL drivers ship inside the jar.
Optional integrations LuckPerms is used when it happens to be installed and is never needed. The one optional bridge is SmartSpawner; without it ItemGuard works exactly the same.

2. Put the jar in place

plugins/
  ItemGuard.jar   # drop it here (or in plugins/ItemGuard/)

Start the server. On the first run the plugin creates plugins/ItemGuard/ with:

  • config.yml — the configuration, fully commented.
  • translations/ — one editable message file per language, nine in all.
  • itemguard.db — the SQLite record. Nothing leaves the machine.

3. Read the start-up report

Every start prints one block that says it all — the first thing to look at when something is not working:

ItemGuard v1.0.0 — by SrIruma & SrPinkyy
State: ACTIVE | 7 tracked item(s)
Server: Paper 1.21.1 (build 133)
Java: 21.0.12.1
Database: SQLite (plugins/ItemGuard/itemguard.db)
Language: en
Loaded: 7 items, 2 template(s)
Integrations: none | SmartSpawner
Sealed ground: on, swept every 30s, 3 reclaim attempt(s)
Access: per-node (17 nodes)

When it cannot start, it names the problem and a fix, instead of stopping on one generic line:

ItemGuard v1.0.0 — by SrIruma & SrPinkyy
State: FAILED | the plugin was disabled
Server: Paper 1.21.1 (build 133)
Engine: MySQL
Problem: cannot open the database on MySQL 8: Access denied for user 'root'
Try: check the database block of config.yml
The engine is named on purpose A wrong password, a missing schema and an unreachable host have nothing in common as a fix. The database line names the engine really in use, with any password= redacted.

4. Guard your first item

Hold a diamond sword and run — with the operator, or itemguard.add granted:

/ig create Sword

This stores the item as template Sword. Hand a guarded copy to a player:

/ig give Steve Sword amount 64

That copy now has a unique id and cannot be dropped or picked up by anyone but Steve. Where is it?

/ig find TI-1a2b3c

Drop it on the ground and seal it into place — bedrock below, a label above:

/ig seal TI-1a2b3c
/ig reclaim                     # its owner takes it back out
Nobody can run commands yet? Every permission defaults to false, so on a real server operators hold nothing until granted. See Permissions. On a test server where everybody joins as operator, set console.ops-are-admins: true and operator status becomes the whole policy.
