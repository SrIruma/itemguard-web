Configuration

The commented config.yml shipped with the jar is the documentation of record. This page goes block by block, with the defaults and the variations.

Written to plugins/ItemGuard/config.yml on first start · /ig reload re-reads everything

The blocks at a glance

lang: default              # message language
server-id: ''              # written on first start; do not edit
database:                  # sqlite | mysql | postgresql
protect-placed-blocks: true
seal:                      # seals, bedrock, sweep, reclaim budget
console:                   # allowlist and ops-are-admins
logging:                   # console / file / detail

lang

lang: default

default is English. Choose es, de, fr, pt-br, it, pl, nl or ru. Any value the plugin does not ship falls back to English with a warning in the console. See Translations.

server-id

server-id: ''

The plugin writes a random id here on first start and the database remembers the one that claimed it. It is what enforces one-database-per-server, so do not edit it by hand. See Database.

database

database:
  type: sqlite        # sqlite | mysql | postgresql
  host: localhost
  port: 0             # 0 uses the engine's default: 3306 or 5432
  name: itemguard
  user: ""
  password: ""
  params: ""          # e.g. "sslmode=require" or "useSSL=true&requireSSL=true"

The last five values are only read for mysql and postgresql. A plain-text password sits here, so keep the file out of version control. See Database.

protect-placed-blocks

protect-placed-blocks: true

Stops other players from breaking blocks that belong to tracked items (chests, spawners, …). These can always break them:

  • the owner of the item;
  • whoever holds itemguard.break.

Explosions do not destroy these blocks either. false restores the old behaviour, where anyone can break them and recover the item.

seal

seal:
  enabled: true
  bedrock: true
  hologram: true
  sweep-seconds: 10
  reclaim:
    max-attempts: 3
    window-seconds: 86400
    radius: 8.0

Explained in full on Seals & reclaim. Every number is clamped so a bad value cannot wedge the server.

console

console:
  allow:
    - give
  ops-are-admins: false

allow is the list of subcommands the console may run — the store-plugin safety valve. ops-are-admins is the test-server switch. Both are covered on Permissions.

logging

logging:
  console: true
  file: false
  detail: normal

file: true writes every line to plugins/ItemGuard/logs/YYYY-MM-DD.log as well as the console; detail: verbose also writes the debug lines. File logging is off by default because a file nobody reads just grows.

Placeholders in item names and lore

Item names and lore support these placeholders, in both a long and a short form:

LongShortBecomes
%ti_id%{id}The unique id of the tracked item
%ti_template%{template}The template it was created from
%ti_owner%{owner}The player the item was delivered to
—{player}The current holder
—{amount}The default amount for the template
—{date}The current date

Reload

/ig reload re-reads config, messages, templates and data, so a change takes effect without a restart. One value is deliberately read once at start-up: console.ops-are-admins, a server-wide policy that must never contradict /ig permissions mid-session.
