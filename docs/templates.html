Templates

A template names a group of items and carries the flags they share. Every item created from it is guarded the moment it lands — no per-item configuration to maintain.

Create from the item in hand · overwrite with force

The idea

A template is a stored copy of the item you held when you ran /ig create, plus a set of flags. When you /ig give from it, the delivered copy is an instance of the group:

  • it inherits the template's flags;
  • it carries its own unique id, so it is tracked independently;
  • it can override any single flag without touching the group.

When the staff upgrade a spawner, the new one is guarded the moment it lands. When they add a second vault key slot, they add one template and every future key behaves.

Creating and managing

/ig create Sword                  # template "Sword" from the item in hand
/ig create Sword force            # overwrite it (keeps the name, takes the shape)
/ig delete Sword                  # remove it
/ig list templates                # everything stored

Without force, creating a name that exists is refused rather than silently replaced.

Delivering from a template

/ig give Steve Sword amount 64

Reads as “make a Sword for Steve”: the item is built from the template, a fresh id is written into its NBT, and the owner is recorded. Options:

OptionEffect
amount <n>Deliver a count instead of the template's default
flags k=v ...Pin flags on this delivery only
rawDeliver without a count (a single item, however it is shaped)
quietDo not notify the recipient
A template is a policy, not a pile Changing a flag on the template changes future deliveries; it does not rewrite items already in the wild. Items pin their own overrides, so a one-off variant costs nothing. See Flags for the precedence.

Examples

A staff-only vault key

/ig create VaultKey                # with a named item in hand
/ig flag VaultKey pickupable=true movable=true hopper-transfer=false
/ig give Alex VaultKey

Keys pass between staff (pickupable, movable) but can never be hoppered away or lost to a drop.

A spawner that survives everything

/ig create Spawner
/ig flag Spawner explosion-protected=true recoverable=true breakable-by-others=false
/ig give Steve Spawner amount 1 flags movable=false

The group is theft-proof by default; this delivery is also immovable, and only this one.

Variations worth knowing

  • Rename-proof — the template name is a key, not a label: overwriting with force changes the shape, never the name.
  • Deleting a template does not delete items already delivered from it — their records and flags are their own.
  • Reloadable — /ig reload picks up template changes without a restart.
