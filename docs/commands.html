Commands

Everything is done through /ig (alias /itemguard). A player sees the result on a screen; the console gets text. Run /ig help in game for the same list, and /ig help gui for it as a menu.

22 subcommands · info, list and flag open a screen for a player

Reference

CommandWhat it does
/ig create <template> [force]Create or overwrite a template from the item in hand
/ig delete <template>Delete a stored template
/ig unlink [id|hand]Stop tracking an item; the item itself is untouched
/ig give <player> <template> [amount <n>] [flags k=v] [raw] [quiet]Build and deliver an item
/ig transfer <player> [id|hand]Send a tracked item to another player
/ig owner <player> [id|hand] [raw]Transfer an item and its ownership
/ig flag <template|id|hand> [flag=value ...]Read the flags on a screen, or change them
/ig recover <id>Take an item back wherever it is, in one piece
/ig regenerate <id> [confirm]Rebuild a lost item from its stored copy
/ig reclaim [id]The owner takes their own sealed item back
/ig seal <id|hand>Seal an item lying on the ground
/ig unseal <id>Take a seal off without moving the item
/ig find <id>Report where an item is
/ig tp <id> [confirm]Teleport to the item: the placed block, the copy on the ground, an online holder, or a container it can see. If none of that is visible it names the reason and waits for confirm
/ig info <id|hand> [history]The record on a screen; history opens the event list
/ig list <templates|items>The catalogue or the tracked objects, on a screen
/ig versionItemGuard, server and Java versions
/ig permissionsEvery ItemGuard node you hold, with a yes or a no
/ig integrationsThe database engine and the optional integrations
/ig reloadReload config, messages, templates and data
/ig help [gui]The full list, as text, or as a read-only menu

The shape of the commands

Options may be written in any order. id means a tracked id such as TI-1a2b3c; hand means the item currently in hand. The shorthand is permissive: wherever an id is needed, hand works.

PieceMeaningExample
id / handRefer to an item by id or by the item in hand/ig flag hand droppable=true
flags k=v ...Pin one or more flags on one delivery only/ig give Steve Sword flags droppable=true recoverable=false
rawDeliver without the count, or transfer ownership without moving the item/ig owner Alex TI-1a2b3c raw
quietSuppress the recipient's notification/ig give Steve Sword amount 64 quiet
confirmAccept a potentially-lossy step (tp or regenerate)/ig tp TI-1a2b3c confirm

A real session

/ig create Sword
/ig give Steve Sword amount 64

/ig find TI-1a2b3c              # in Steve's inventory
/ig seal TI-1a2b3c              # Steve drops it, you seal it
/ig reclaim                     # Steve takes it back
/ig info TI-1a2b3c              # the whole story, on one screen

The console

The console is blocked by default: it may only run the subcommands listed in console.allow, which defaults to give. That is what lets a store plugin such as Tebex fulfil a purchase without being handed full control.

console:
  allow:
    - give

A few read-only subcommands bypass the list entirely: version, reload, help, integrations, permissions and allow. None of them can create, move or delete a tracked item, which is what makes them safe. /ig allow is the console view of the allowlist.

Not sure who can run what? /ig permissions prints every node with a yes or a no and needs no permission of its own — the people who need it are exactly the ones who cannot run anything else. See Permissions.

Alternatives and variations

  • /ig help gui — the command list as an in-game chest menu, reading only. Same facts, different surface.
  • hand everywhere — you rarely need to type an id: /ig info hand, /ig seal hand, /ig unlink hand.
  • Screens — /ig info, /ig list and a bare /ig flag open a menu for a player instead of printing. See In-game screens.
